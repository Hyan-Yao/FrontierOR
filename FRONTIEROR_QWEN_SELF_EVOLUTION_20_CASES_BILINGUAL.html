1. archetti2007 No explicit license error

Failure vs expert

The one-shot defines only upper-triangular undirected variables x[i,j,t] but later requests both directions inside MTZ constraints, causing KeyError (2,1,1). OpenEvolve turns the graph directed and runs, yet violates depot degree, shipment/inventory, or extended-horizon consistency; its reported 1273.7973 is therefore not a valid improvement over the expert 1750.3217. CORAL likewise moves from infeasible exact models to a 4652.63 greedy plan that still fails the checker.

The expert keeps continuous deliveries and inventory, visit binaries, one canonical undirected edge accessor with depot multiplicity two, exact extended-horizon balance, and lazy subtour separation. The difference is not one missing constraint: it is a coordinated set of representation invariants.

与专家对照

One-shot 只建立上三角无向变量 x[i,j,t]，MTZ 却按两个方向取值，直接产生 KeyError (2,1,1)。OpenEvolve 改成有向图后虽能运行，却破坏仓库度数、配送/库存或扩展周期一致性，所以 1273.7973 不是相对专家 1750.3217 的有效改进。CORAL 也从不可行精确模型退到 4652.63 的贪心方案，仍未通过 checker。

专家代码同时维护连续配送量、库存、访问变量、带仓库双重计数的规范无向边访问器、精确扩展周期平衡与 lazy subtour。差距不是少一条约束，而是一组必须协同成立的表示不变量。

2. bard2002 No explicit license error

Failure vs expert

The one-shot uses 8 vehicles on tiny versus the expert's 1, and crashes on harder instances. Its nearest-neighbor loop keeps state from the last examined customer rather than the selected customer; its local search also forbids emptying a source route—the precise move required to reduce vehicle count. Evolution discovers meaningful progress: OpenEvolve and CORAL reach 2 vehicles, and CORAL matches some held-out vehicle counts, but the hard 10% pass gate maps 2 versus 1 to score zero and hides the gain. Some equal-count outputs still fail time/load checks.

The expert builds only time-feasible directed arcs, minimizes depot departures, and enforces exact service, flow, time and load potentials. It optimizes the actual feasibility geometry rather than repairing routes after construction.

与专家对照

One-shot 在 tiny 用 8 辆车，而专家只需 1 辆，并在更难实例崩溃。其最近邻循环保存的是“最后检查客户”而非“最终选中客户”的状态；局部搜索还禁止清空源路线，而减少车辆恰恰需要这一动作。演化确有进步：OpenEvolve、CORAL 都做到 2 辆，CORAL 在部分留出集也匹配车辆数，但 10% 硬阈值把 2 对 1 直接压成 0 分，掩盖了进展；部分同车辆数结果仍违反时间/载重。

专家只建立时间可行的有向弧，以仓库出发数为目标，并精确约束服务、流、时间和载重势能；它直接搜索真实可行域，而不是事后修路线。

Improve / 改进：Use lexicographic fitness—feasibility first, then normalized vehicle gap, then distance/runtime—and allow route-eliminating neighborhoods. Return exact load/time violation witnesses instead of a single zero. / 使用字典序适应度：先可行性，再车辆数归一化差距，最后距离/时间；允许消除整条路线的邻域，并返回精确载重/时间违反证据而非单一 0 分。

3. bront2009 No explicit license error

Failure vs expert

The one-shot's fixed pool of hand-designed offer sets earns 4860 on tiny versus the expert's 7900, then reuses nearly the same behavior on large instances, with 93–95% gaps. CORAL's selected program falls further: held-out gaps are 96.83–97.41%. Three rounds mostly reorder or perturb the same static pool; they cannot invent the missing feedback loop.

The expert solves a restricted master LP, reads resource dual prices, and repeatedly prices a new offer set—first greedily, then with an exact MIP—until no positive reduced-cost column remains. This is an algorithm-family mismatch: surface-level mutation of a heuristic cannot reproduce dual-guided column generation.

与专家对照

4. carvalho1999 No explicit license error

Partial success vs expert

This is the strongest heuristic baseline: first-fit/best-fit decreasing plus simulated annealing passes 5 of 6 instances and is exact on large_3/4. CORAL reaches the development reference 8334, but its selected large-instance path largely returns to the original heuristic, adds overhead, and does not improve held-out quality. 10. adulyasak2015 License only after evolution

Failure vs expert

The one-shot fails before solving: customers are numbered 1…n, while scenario-demand arrays are 0…n-1; it reads demand[i] instead of demand[i-1]. OpenEvolve and EoH change routing constraints and tuning but preserve that traceback for all three rounds. CORAL revision 1 finally fixes the index, exposing a second barrier: the exact 100-scenario tiny MIP exceeds the restricted license. Revision 3 avoids the error by replacing scenarios with expected demand and reports 1055.2954, but that solves a different deterministic approximation and is not comparable to the expert stochastic optimum 1395.7594.

The expert preserves shared first-stage setup/routes and scenario-specific production/inventory recourse, with centralized index mapping and lazy subtour separation.

与专家对照

One-shot 尚未求解便失败：客户编号为 1…n，场景需求数组为 0…n-1，代码读取 demand[i] 而非 demand[i-1]。OpenEvolve、EoH 三轮都改了路径约束或参数，却一直保留同一 traceback。CORAL 第 1 次才修复索引，随即暴露第二层障碍：100 场景精确 tiny MIP 超出受限许可证。第 3 次用期望需求替代场景并报 1055.2954，但这已是另一个确定性近似，不能与专家随机最优值 1395.7594 直接比较。

What to change in test-time evolution / 如何改进测试时演化

Recommended architecture
  1. Structured outcome, not one scalar: record syntax/runtime/schema/feasibility, violation count and magnitude, normalized objective gap, final quality, AOCC, runtime, and license_blocked separately.
  2. Lexicographic archive: select by executable → schema-valid → feasible → smaller violation → objective → runtime; preserve every Pareto-best and best-known-valid candidate. A missing metric cannot beat observed correctness.
  3. Counterexample-guided repair: provide traceback plus the top checker violations and a minimal failing witness. Iteration 1 should make the smallest causal repair; later iterations may optimize.
  4. Contract-first representations: generate/test ID maps, index bases, canonical edge access, depot closure, immutable route IDs and serialized schema before solving.
  5. Structural algorithm choice: recognize column generation, lazy separation, arc flow, scenario decomposition and flow formulations. Reserve at least one candidate per round for a different algorithm family.
  6. License-aware routing: estimate model size before construction; use reduced instances, decomposition or solver-free heuristics/verifiers. Never catch license errors as valid objectives.
  7. Curriculum and regression: tiny unit cases → adversarial tiny variants → reduced development → full development → held-out. Fix random seeds, repeat stochastic trials and reject regressions.

  1. 结构化结果而非单一分数：分别记录语法/运行/schema/可行性、违反数量和幅度、归一化目标差距、最终质量、AOCC、时间与 license_blocked。

Expert code / 专家代码

The reference first computes all-pairs longest temporal paths with Floyd–Warshall, yielding tight earliest/latest start windows. It creates monotone step variables only inside those windows; start-time pulses are differences of adjacent steps. For each partially renewable resource, exact overlap is expressed by step differences over only relevant periods, so no separate activity×resource×period usage binary or fragile iff linearization is needed. / 参考实现先以 Floyd–Warshall 计算全部最长时间路径，得到紧致最早/最晚开始窗口；只在窗口内创建单调阶跃变量，并以相邻阶跃差表示开始脉冲。对每个部分可再生资源，利用相关时段上的阶跃差精确表达重叠，因此无需额外“活动×资源×时段”使用变量，也无需脆弱的 iff 线性化。

Why no success? / 为何未成功

The key modeling object is the start-time pulse, not an independently selectable “active at period” flag. One-shot and all CORAL revisions stay with the latter, causing both an enormous model and a missing reverse implication. OpenEvolve/EoH occasionally remove enough structure to run, but then optimize a relaxation and expose the impossible 20 objective. None of the three feedback loops discovers the expert's temporal-window preprocessing plus step-difference identity within three iterations; without that structural pivot, a full license would only make an incorrect or inefficient model runnable. / 关键建模对象应是开始时间脉冲，而非可独立选择的“某时段活跃”标志。one-shot 与全部 CORAL 修订坚持后者，同时造成巨型模型和缺失反向蕴含。OpenEvolve/EoH 偶尔删掉足够结构而能运行，却转而优化松弛模型，产生不可能的目标 20。三轮内没有框架发现专家的时间窗口预处理与阶跃差恒等式；没有这次结构转向，即使升级许可也只是让错误或低效模型得以运行。
